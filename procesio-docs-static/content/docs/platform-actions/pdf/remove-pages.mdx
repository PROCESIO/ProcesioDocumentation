The **Remove Pages** action makes a new PDF that leaves out the pages you choose, for example a blank last page or an internal cover sheet. The remaining pages keep their original order.

## Add the action [#add-the-action]
In the Process Designer toolbox, open **PDF** and pick **Remove Pages** (or type *Remove Pages* in the search box).

![The Remove Pages action properties: Input file, Page Selection and Resulting File](/images/docs/actions/pdf-remove-pages/panel.png)

## Inputs and outputs [#inputs-and-outputs]
| Field | Direction | Type | Required | What to put / what you get |
| --- | --- | --- | --- | --- |
| **Input file** | Input | File | Yes | The PDF to remove pages from. |
| **Page Selection** | Input | Text | Yes | The pages to remove, **one selection per row**. A row is a page number (`3`) or a range (`5-7`). Press Enter between selections. |
| **Resulting File** | Output | File | Yes | A new PDF with the remaining pages. |

## Example [#example]
With a 3-page **Input file** `invoice.pdf`:

| Page Selection | Resulting File |
| --- | --- |
| `2` | pages 1 and 3, named `invoice.pdf_Leftover.pdf` |
| `1-3` | The step fails: `Cannot save a PDF document with no pages.` |

In the same way, on a 10-page file the two rows `3` and `5-7` would leave pages 1, 2, 4, 8, 9 and 10.

## Good to know [#good-to-know]
- Pages are numbered from 1. The order of the rows does not matter.
- Removing every page fails the step, as shown above.
- A page number above the page count fails the step with `Invalid selection on row … : Value … is greater than input file page count !`
- Rows accept only a number or a `from-to` range. The input must have the `.pdf` extension.
