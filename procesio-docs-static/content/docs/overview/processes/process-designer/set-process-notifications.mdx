Process notifications send an email when a run of your process ends. You choose who receives it and whether to send it when the run succeeds, when it fails, or both.

There are two kinds:

- **General Process Notification**: an email for every run of the process, whatever started it (a user, a schedule or an external source such as a webhook or an API call).
- **Scheduled Notifications**: an email only for the runs started by one schedule of the process. Each schedule has its own settings.

## Open the notification settings [#open]

You can open them in two places:

- **From the processes list.** In the process row, click the email icon, or open the row's menu and click **Set process notifications**. The icon's tooltip tells you whether notifications are set: *"Notifications are set"* or *"Notifications not set"*.
- **From the Process Designer.** In the right-side tabs, click the email icon (**Process notifications**).

The **Set Process Notifications** panel opens.

You need permission to edit the process to change its notifications. Otherwise the settings are read-only.

## Set the general notification [#general]

1. Expand **General Process Notification**.
2. Turn on **Set email notifications**.
3. In **Email addresses**, type one or more addresses. Separate them with a semicolon, for example `ana@example.com;ion@example.com`.
4. Under **Notification type**, check one or both:
   - **Notify when run is success**
   - **Notify when run is failed**

   If you clear both, the panel shows *"You need to select a type from above in order to complete the notification configuration."*
5. Close the panel.

There is no **Save** button: your changes are saved as you make them. An address that is not valid is marked in red under the field.

## Set notifications for one schedule [#schedule]

If the process has schedules, **Scheduled Notifications** lists them, each with **Notification set** or **Notification not set**. If it has none, you see *"You don’t have any schedule set for this process."*

1. Expand **Scheduled Notifications** and click a schedule.
2. The panel shows whether the schedule is **Enabled** or **Disabled** and how often it runs.
3. Set **Set email notifications**, **Email addresses** and **Notification type** the same way as above.
4. Click the schedule name at the top (or **Back**) to return to the list.

These settings apply only to that schedule and do not change the general notification. You can also set a schedule's notifications when you create or edit it. See [Schedules](/schedules).

<Callout type="info">
The general notification covers every run, including the runs started by a schedule. Turn it on only if you want an email for all runs.
</Callout>

## What the email contains [#email]

The email tells you how the run ended and includes the ID of the workspace the process belongs to, so you can tell runs from different workspaces apart.
