Scheduled processes are automated processes that can be performed at a specific time or on a recurring schedule.

If you have a process that needs to be run:

- once, on a specified date or time or 
- on a regularly recurring basis, say once a week, twice a month or once a year, you can schedule your process in&#xA0;**&#x20;Schedules page** to run automatically.

The scheduler automatically runs a process for you. You can add contacts that will receive an email notification based on process completion status (completes/fails/both).

Below are some examples of scenarios requiring scheduled processes:

- To schedule an onboarding flow for your new employees.
- To create monthly payroll files.
- To create annual reports at the end of financial year.

<Callout type="info">
If you need the same process to recur at different dates and times, you are able to set that. If you have set up at least one schedule for a process, you can duplicate that schedule and change some settings as needed. This will save you time on setting the next one.
</Callout>

### How to set up a schedule

**Step 1**: Go to **Schedules page.**

**Step 2**: Click **Create New.**

![](/images/docs/A-EuXGhAtJKwPVzkHcAmj_screenshot-2022-06-02-at-222254.png)

**Step 3**: Give a **Name&#x20;**&#x74;o your schedule.

**Step 4**: Add a **Description** to help others identify the scope of the schedule (optional).

**Step 5**: Select the Process you wish to use the schedule on.&#x20;

> In the list, you will notice that processes are marked **Valid/Invalid** (meaning that there are errors in process configuration that must be fixed) or **Active/Inactive&#x20;**(meaning that a process is deactivated and execution cannot be initiated until switched to an active state).&#x20;

An **inactive** process cannot be scheduled. If you select one, the message _"This process is inactive, so the schedule would never run. Activate the process or select another one."_ is shown and the **Save** button stays disabled. Activate the process first, or select another one.

If a process is **invalid**, you can still configure the schedule, however, it will not run at the set start date and time.

![](/images/docs/f9cvzaycQ1REWuS-nXQkP_screenshot-2022-06-02-at-222659.png)

**Step 6:&#xA0;**&#x53;et Recurrence details

**Start on**: The start date and time are required fields and it’s where you can select the date and time that your first scheduled process will be run on.

<Callout type="info">
**Start time** will reflect your local Time zone. You can only schedule processes to run on future dates and times. The days you pick (weekdays, day of the month) and the start time follow the time zone of your browser when you save the schedule. Schedules created before PROCESIO v2.0.7 keep the previous behaviour until you open them and save them again.
</Callout>

Then choose how the schedule repeats: **Basic Recurrence** (the default, described below) or **Crontab**, for a crontab expression. See [Crontab recurrence](#crontab-recurrence).

With **Basic Recurrence**, the **Run interval** dropdown menu will let you select how often your process will be run.

- Once means that your process run will not be repeated – it will only run once, at the date and time you select, for example at the date and time of an upcoming meeting
- Minutes runs your process every set number of minutes, for example every 15 minutes. 
- Hourly runs your profess every set number of hours, for example every 6 hours. 
- Daily runs your process every day for example every day. You can also exclude weekend days.
- Weekly lets you select one or more days of the week the process will run. For example, every week on Monday and Friday
- Monthly will schedule your process to run every month in a specific day (1,2 or Last day of month). You can also choose to repeat on either the same day of the month as the first or the last day of the week (First Monday). 
- Yearly runs your process every year. You can choose to repeat on the same day (Every March 10) or the same day of the month as the first or the last day of the week (Last Friday of December).

Date to end schedule: select the checkbox to access the field that let you select when your scheduled process runs will be due to be finished.

<Callout type="info">
Once the recurrence is configured, read the summary at the bottom and double-check that the settings details are correct.
</Callout>

![](/images/docs/HTd0dIjFRJUB7p0xYrCk7_recurence.png)

<Callout type="info">
We do not recommend a frequency lower than 5 minutes at this point.
</Callout>

### Crontab recurrence [#crontab-recurrence]

Choose **Crontab** when the basic options can't express the timing you need, for example *"at 09:00 on weekdays"* or *"on the second Monday of every month"*.

A crontab expression has five fields, each in its own box:

| Field | Values |
| --- | --- |
| **Minute** | `0`–`59` |
| **Hour** | `0`–`23` |
| **Day** | `1`–`31` (day of the month) |
| **Month** | `1`–`12`, or `JAN`–`DEC` |
| **Weekday** | `0`–`7`, or `SUN`–`SAT`. Both `0` and `7` mean Sunday. |

Each field starts as `*` (any value), so a new expression is `* * * * *`, every minute. There is no field for seconds. If you paste a whole expression such as `0 9 * * MON-FRI` into one box, it is split across the boxes for you.

You can combine values with these operators:

| Operator | Meaning | Example |
| --- | --- | --- |
| `*` | any value | |
| `,` | a list | `1,5,10` |
| `-` | a range | `MON-FRI` |
| `/` | a step | `*/15` |
| `L` | last (Day and Weekday) | `L`, `FRIL` |
| `W` | nearest weekday (Day only) | `15W` |
| `#` | the nth weekday of the month (Weekday only) | `MON#2` |

Some examples:

| Expression | Runs |
| --- | --- |
| `0 9 * * *` | Every day at 09:00 |
| `0 */6 * * *` | Every 6 hours |
| `0 9 * * MON-FRI` | Weekdays at 09:00 |
| `0 8 1 * *` | The first day of every month at 08:00 |
| `0 18 L * *` | The last day of every month at 18:00 |
| `0 9 LW * *` | The last weekday of every month at 09:00 |
| `0 10 * * MON#2` | The second Monday of every month at 10:00 |

<Callout type="warn">
**Day and Weekday combine with AND.** When you set both, the schedule runs only on days that match both: `0 0 13 * FRI` runs only on a Friday the 13th, and `0 0 29 2 MON` only when 29 February is a Monday. Some other crontab tools treat this as OR, so check the preview.
</Callout>

As you type, PROCESIO checks the expression. A valid expression shows a short description and a list of the **next 5 occurrences**, in the schedule's time zone. An invalid one shows what is wrong. If the expression is valid but never runs, for example `0 0 30 2 *` (30 February), or the end date is already in the past, you see *"No upcoming runs"*. You can't save the schedule while the expression is invalid, still being checked, or has no upcoming runs. Open **Syntax help** above the boxes for the format, the operators and these examples.

**Time zone.** A new crontab schedule uses the time zone of your browser, shown above the occurrence list. When you edit a schedule that was created in another time zone, a message tells you so, and the schedule keeps its original time zone when you save it.

The **Start on** date and **Date to end schedule** also apply to a crontab schedule: no run happens before the start or after the end.

{/* SCREENSHOT: crontab-recurrence.png — the Crontab option with the five fields filled in, the description and the next 5 occurrences */}

<Callout type="info">
If you switch an existing schedule between **Basic Recurrence** and **Crontab**, saving replaces its previous recurrence settings. A message warns you before you save.
</Callout>

**Step 7:&#xA0;**&#x4E;otifications

PROCESIO can send notifications to users informing them on the completion of a scheduled process. This is an optional step. You can add email addresses (yours or others within workspace) to receive an email notification once the scheduled process has run.

Users can be notified based on completion status of the process:

- only when process run successfully
- only when process failed
- both

<Callout type="info">
You can add multiple email addresses using ";" as a separator.
</Callout>

![](/images/docs/nyX1l0Td0TJ-WRWvtMCk5_notifications.png)

**Step 8:&#xA0;**&#x43;lick **Next** to move to the next configuration step

**Step 9**: Give values to your Process Input(s)

If the process selected to be scheduled has input process variables defined at process level, you must give values to these variables in order for the process to kick off with desired values. Else, the inputs variables will get the system default value based on data type (e.g. a process variable type integer will get 0 value when initiating the process). 

![](/images/docs/Wbv9JAQqWO6q3lmcKLSnA_createschedule1.png)

**Step 10: Save** your schedule

### **Managing the schedules**

You can view the schedules created i&#x6E;**&#x20; Schedules page**.

From here you can update or change the settings to a schedule, duplicate a schedule or delete a schedule. 

![](/images/docs/kHck_0stzN5sEInpuU2cz_screenshot-2022-06-02-at-223347.png)

You can also **Enable**/**Disable&#x20;**&#x61; schedule. You may encounter a situation that requires you to disable the scheduler for one or more processes, such as during maintenance periods, holidays or when execution of one process may interfere with another. In such cases, you can disable one or more processes from starting automatically. When you disable a workflow, the Schedule does not run the process until you enable it back.

<Callout type="info">
Use the status toggle to disable/enable your processes.
</Callout>

![](/images/docs/Ju3ppzORMqSbakfbfe20z_automation5.png)

<Callout type="info">
If the process is set to run once, it will be automatically disabled after it runs. Also, if a process has an end date set, it will automatically be disabled once the end date is passed. You must edit and update the schedule to a future start date and time.
</Callout>
