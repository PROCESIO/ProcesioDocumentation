## What these use cases have in common

Each one has at least one of these, and that is what separates it from a simple link between two apps:

- **State.** A document moves through several statuses, and the process has to know where each one is.
- **A deadline set from outside.** A filing window, a reporting clock, a re-check interval.
- **A person in the loop.** Someone approves, corrects or fills in what the data couldn't answer.
- **A record for later.** An auditor will ask what happened to a specific document, a year from now.

That combination is what PROCESIO is built for. See [Why PROCESIO](/why-procesio) for the platform side.
